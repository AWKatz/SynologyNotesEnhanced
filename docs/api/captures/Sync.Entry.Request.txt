Source: SYNO Sync.har.txt (2026-06-21) — NoteStation web client startup/sync.
All POSTs to /notestation/webapi/entry.cgi, form-urlencoded.
Note the CSRF headers on every POST: X-SYNO-TOKEN: <REDACTED>  (+ X-SYNO-HASH, incrementing).

═══ 1. Startup batch — SYNO.Entry.Request v1 (the "sync") ═══
Request (decoded):
  api=SYNO.Entry.Request&method=request&version=1
  &stop_when_error=false
  &mode="sequential"
  &compound=[
    {"api":"SYNO.NoteStation.Notebook","method":"list","version":2},
    {"api":"SYNO.NoteStation.Note","method":"list","version":3,
       "filter":{"fast_result":true},"field":{"commit_msg":true}},
    {"api":"SYNO.NoteStation.Tag","method":"list","version":1},
    {"api":"SYNO.NoteStation.Shortcut","method":"list","version":1},
    {"api":"SYNO.NoteStation.Todo","method":"list","version":1},
    {"api":"SYNO.NoteStation.Smart","method":"list","version":1}
  ]

Response envelope:
  {"data":{"has_fail":false,"result":[
     {"api":"SYNO.NoteStation.Notebook","method":"list","version":2,"success":true,"data":{...}},
     {"api":"SYNO.NoteStation.Note","method":"list","version":3,"success":true,"data":{...}},
     ... one entry per compound item, in order ...
  ]},"success":true}

  → result[i] aligns with compound[i]. Each has its own success flag.
  → Outer has_fail summarizes; stop_when_error=false means failures don't abort the rest.

═══ 2. Standalone Note.list — SYNO.NoteStation.Note v3 ═══
Request (decoded):
  api=SYNO.NoteStation.Note&method=list&version=3
  &filter={"recycle":false,"owner":1026,"archive":false}
  &field={"link_id":true,"commit_msg":true}
  &offset=0&limit=50
  &sort_by="title"
  &sort_direction="desc"

  ⚠ Real client uses v3, structured filter/field OBJECTS, and sort_direction
    (NOT v4 / order / fields-csv that our service currently sends).

═══ 3. Attachment / thumbnail fetch — SYNO.NoteStation.Note method=download v3 (GET!) ═══
  GET /notestation/webapi/entry.cgi?api=SYNO.NoteStation.Note&method=download&version=3
    &object_id="1026_OFUIQRDCA135H98QFHL7UHRGOO"
    &format="raw"
    &md5="4f16df36fa8bb445edd06d0c0b69d134"
    &file_id="thumb"
    &filename="thumb.png"
    &SynoToken=<REDACTED>          ← CSRF token as QUERY param on GETs
  → returns raw image bytes. md5 + file_id come from the note's thumb/attachment object.

═══ 4. UI prefs persistence — SYNO.Core.UserSettings method=apply v1 ═══
  data="{\"SYNO.SDS.NoteStation.Application\":{view_by:\"snippet\", sort_info:{sort_by,sort_direction},
        todo_filter_date/priority/status, notebook_full_menu_states:{...}, snippetview_width, restoreSizePos}}"
  → view_by = card|snippet|... , sort prefs, todo filters all live here (double-JSON-encoded string).
  → This is where card/snippet/presentation view choice persists, server-side.
