Source: <NAS> HAR (2026-06-21 17-17-46) — opening encrypted notes in the stock client.

KEY FINDING: Decryption is 100% CLIENT-SIDE. There is NO server "decrypt" API.
The note's `content` is stored encrypted; Note.get returns the encrypted blob and the
web client decrypts it locally with the user's password. (During the whole decrypt
session NO SYNO.NoteStation.Note.Encrypt call is made — only Note.get.)

═══ Encrypted note content format ═══
Note.get on an encrypted note (encrypt=true) returns:
  content = "U2FsdGVkX1...."   (base64)
Base64-decodes to the OpenSSL / CryptoJS "Salted__" envelope:
  "Salted__" (8 bytes) + salt (8 bytes) + AES-CBC ciphertext
Cipher:  AES-256-CBC
KDF:     OpenSSL EVP_BytesToKey with MD5, 1 iteration, over (password + salt)
         → first 32 bytes = key, next 16 bytes = IV
Padding: PKCS#7

Verified with openssl against the real blob (password "12345"):
  openssl enc -d -aes-256-cbc -md md5 -pass pass:12345 -base64 -A -in blob.b64

═══ Plaintext shape (password-correctness check) ═══
Decrypted plaintext = "NoTeStAtIoNMaGic" + <the note's HTML content>
  → If the decrypted text starts with the magic marker, the password is correct;
    strip the 16-char marker to get the real HTML.
  → Wrong password ⇒ PKCS#7 unpad fails OR the marker is absent. Either ⇒ "wrong password".

Real example (test/fixtures/encrypted_note_12345.b64, password "12345"):
  → "NoTeStAtIoNMaGic<h1>HEADING 1</h1><h2>HEADING 2</h2>...<hr id=\"ext-gen1182\" /></div>"

═══ Re-encrypt / change-encryption (for reference, from the duplicate flow) ═══
SYNO.NoteStation.Note.copy v3 with `old_password="12345"` + `encrypt=false` decrypts on
the server side when duplicating. Setting encryption on a note = SYNO.NoteStation.Note.Encrypt
create v1 (object_id, password, duration) → token (see Note.Encrypt.txt). Writing NEW
encrypted content from our app (encrypt locally + save) is NOT yet captured — read-only for now.
